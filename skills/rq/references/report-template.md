# 요구사항 품질 게이트 보고서 양식

전체 Markdown 보고서를 작성할 때 사용한다. 전달 위치와 최종 응답은 [보고서 전달](report-delivery.md), 한국어 값은 [표시값 규칙](korean-report-values.md)을 따른다. 제목·라벨·값·설명은 사용자 언어로 작성한다.

## 작성 규칙

- 읽는 사람이 첫 세 줄만 보고 상태와 판정 이유를 알 수 있어야 한다. 중요한 정보부터 쓰고 같은 내용을 여러 절에서 반복하지 않는다.
- 아래 양식 외의 절·표·열을 추가하지 않는다. 내부 판단 과정, 조사 경로, 검색 결과 목록은 보고서에 쓰지 않는다.
- 표의 각 칸은 한 구절로 쓴다. 근거 칸에는 `path:line` 1~2개와 확인한 동작만 적고 코드 블록이나 긴 설명을 넣지 않는다.
- `(선택)` 줄은 해당 내용이 있을 때만 쓰고, 나머지 줄은 내용이 없으면 `없음`으로 쓴다.

## 양식

```markdown
# 품질 게이트

**<통과 / 경고 / 실패 / 검토 필요 / 관련 변경 없음 / 오류>** · <경량 검토 / 심층 검토> · <현재 게이트만 평가한 판정 한 문장>

> <원 요구사항만 인용한다. 검토 범위, 제공된 증거와 제한은 제외한다.>

## 기준

| ID | 기준 | 영역 | 상태 | 근거 |
|---|---|---|---|---|
| AC-1 | <요구 동작> | <코드 / 테스트 / 마이그레이션> | <충족 / 위험 동반 충족 / 미충족 / 확인 불가> | <`path:line`: 확인한 동작> |

범위 밖 (집계 제외 · 영향 없음): <실행·배포·데이터·수동 확인 등 판정하지 않은 원 의무 또는 없음>

## 위험과 조치

| 심각도 | 위험 | 조치 | 기준 |
|---|---|---|---|
| <치명적 / 높음 / 중간 / 낮음> | <현재 범위의 구체적 위험> | <권고 조치> | <AC-n> |

## 검토 정보

- 대상: <ref·PR·MR·작업 트리> (<merge-base 비교 / 직접 diff / 스테이징 변경 / 미스테이징 변경 / 혼합 / 제공된 diff>)
- 증거: <코드 증거 / 실행 증거 / 혼합 증거>; 실행한 검증 <`명령` → 결과 또는 없음>
- 독립 검토: <요구사항 → 검토자: 결과>; 이견 <해소 내용 또는 없음>
- 제한: <누락된 증거·미실행 검증·미연결 변경 파일 또는 없음>
- (선택) 모호성: <문구 충돌과 해소 방식, 결과 영향>
- (선택) 별도 게이트: <게이트: 상태, 분리 이유; 현재 게이트 영향 없음>
```

## 절별 기준

- 기준 표에는 원 요구사항에서 도출한 범위 내 기준만 둔다. 범위 내 기준은 모두 종합 상태에 반영되므로 범위·영향 열을 두지 않는다. 증거만 설명하는 문장은 승인 기준이 아니다.
- 범위 밖 의무는 표에 넣지 않고 `범위 밖` 줄에 나열한다. 이 줄의 항목은 종합 상태에 영향을 주지 않는다.
- 위험과 조치 표에는 상태를 낮춘 위험과 비차단 권고만 우선순위 순으로 둔다. 위험과 권고가 모두 없으면 표 대신 `없음`을 쓴다.
- 별도 게이트에는 독립 원 요구사항으로 나눈 다른 구현 게이트만 기록한다. 운영 실행·배포·데이터·수동 확인은 별도 게이트로 만들지 않는다. 독립 게이트의 증거 부재로 현재 게이트 상태를 낮추지 않는다.
- 독립 검토의 배정과 완료 여부는 [독립 검토](independent-review.md)에 따라 확인한다. 미완료이면 해당 요구사항을 `독립 검증 미완료`로 표시한다.

## 선택적 적대적 검증 부록

사용자가 보고서 후속 적대적 검증을 명시적으로 요청한 경우에만 보고서 끝에 추가한다. 검토 방식은 [독립 검토](independent-review.md#보고서-후속-적대적-검증), 추가·갱신·실패 처리는 [보고서 전달](report-delivery.md)을 따른다.

```markdown
## 적대적 검증 부록

**기존 판정 <유효 / 수정 필요>** · 요청: <사용자 요청 문구> · 배정: <요구사항 → 검증자>

| 기준 | 결과 | 근거·반례 | 반영 |
|---|---|---|---|
| AC-1 | <유지 / 변경 필요> | <일차 증거 또는 시도한 반례> | <수용·기각 이유와 상태 변경> |
```
